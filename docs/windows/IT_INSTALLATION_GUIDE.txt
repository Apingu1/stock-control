============================================================
1. PACKAGE CONTENTS
============================================================

IMPORTANT DISTRIBUTION NOTE

Do NOT use GitHub's Code > Download ZIP as the installation package. That downloads the developer/source repository and will contain api, db, infra, web, windows and other source folders at the root.

Use the validated GitHub Actions artifact named:

Pharmagrowth-Stock-Control-Commercial-Package

or the locally generated:

release\Pharmagrowth-Stock-Control-Commercial-Package.zip

The GitHub Actions artifact only needs to be extracted once. After extraction, the user should see a single folder named:

Pharmagrowth Stock Control

At the top level IT should see:

00 - START HERE - INSTALLATION GUIDE.txt
01 - INSTALL SERVER.bat
02 - START SERVER.bat
03 - STOP SERVER.bat
04 - SERVER STATUS.bat
CLIENT DEPLOYMENT\
Administration & Recovery\
Documentation\
System\

The System folder contains controlled server runtime files. IT should not run files directly from System during a normal installation.

No self-extracting server or client EXE is required or created.

============================================================
2. SERVER PREREQUISITES
============================================================

- Windows 10/11 Pro or another approved Windows host environment.
- Docker Desktop installed and configured for Linux containers.
- Docker Desktop running before installation.
- Administrator access.
- Stable private LAN IPv4 address or DHCP reservation.
- TCP 8443 permitted between client computers and the server.
- TCP 8088 may be retained for local diagnostics if approved.

Do not run the live database/application from a mapped network drive. The commercial launcher copies the controlled application files to:

C:\ProgramData\Eaststone\StockControl

before starting the server installation.

============================================================
3. INSTALL THE SERVER
============================================================

1. Extract the complete Pharmagrowth Stock Control package to a local folder.
2. Start Docker Desktop and wait until Docker is running.
3. Right-click "01 - INSTALL SERVER.bat" and select "Run as administrator".
4. Accept the Windows UAC prompt.
5. The installer copies the controlled server files to C:\ProgramData\Eaststone\StockControl.
6. Confirm the server's private LAN IPv4 address if automatic detection cannot determine it.
   Typical private addresses begin 10.x.x.x, 172.16-31.x.x or 192.168.x.x.
7. Leave the installer window open until "Server setup completed" is displayed.
8. Open https://stock-control.test:8443/.
9. Initial login: admin / Admin123!
10. Change the administrator password immediately.
11. Review the generated IQ report before approving the installation:

C:\ProgramData\Eaststone\StockControl\deployment-records\ESC-IQ-Execution-Latest.html

The server setup configures the database, application, HTTPS certificate, trusted private CA, local hostname, firewall rules, scheduled health monitoring, certificate renewal, daily backup and application shortcuts.

============================================================
4. CLIENT DEPLOYMENT
============================================================

The BAT-based client setup is already included in CLIENT DEPLOYMENT when the commercial package is downloaded.

Before server installation the folder contains:

01 - INSTALL CLIENT.bat
Configure-Hosts.ps1
client-config.ini
README.txt

Do not distribute or run the client setup before the server installation completes. At that stage the client-config.ini does not yet contain the server IP and the public Stock Control CA certificate does not yet exist.

During server installation, "01 - INSTALL SERVER.bat" does NOT build or create a client installer or EXE. It only updates the existing CLIENT DEPLOYMENT folder by:

- writing the actual server hostname/IP into client-config.ini
- adding stock-control-ca.crt, the public Stock Control CA certificate

After successful server installation the folder should contain:

01 - INSTALL CLIENT.bat
Configure-Hosts.ps1
client-config.ini
stock-control-ca.crt
README.txt

To configure another Windows computer:

1. Copy the COMPLETE CLIENT DEPLOYMENT folder to the client computer.
2. Confirm the client computer can reach the server on the company network.
3. Right-click "01 - INSTALL CLIENT.bat" and select "Run as administrator".
4. Accept UAC.
5. Client setup imports the public Stock Control CA, maps stock-control.test to the server LAN IP, creates the application shortcut and verifies HTTPS access.
6. Open the Eaststone Stock Control shortcut.
7. Log in using that user's individual Stock Control account.

Never copy server private keys to a client. Only stock-control-ca.crt is distributed.

============================================================
5. NORMAL SERVER CONTROLS
============================================================

Use only the top-level controls during routine operation:

02 - START SERVER.bat
03 - STOP SERVER.bat
04 - SERVER STATUS.bat

The controlled stop preserves the PostgreSQL data volume. Do not use "docker compose down -v" during routine operation because -v destroys the database volume.

============================================================
6. ADMINISTRATION, RECOVERY AND COMPLETE UNINSTALL
============================================================

Administration & Recovery contains:

01 - BACKUP AND RESTORE.bat
02 - COMPLETE UNINSTALL.bat
README.txt

"02 - COMPLETE UNINSTALL.bat" is the ONE supported uninstall control in the commercial package. There is no second UNINSTALL_WINDOWS.bat under System and there is no uninstall EXE.

Complete uninstall requires explicit confirmations before destroying the PostgreSQL data volume and generated application data. It can also remove:

Installed application:
C:\ProgramData\Eaststone\StockControl

and, separately when explicitly confirmed, the local extracted:
Pharmagrowth Stock Control\

If the commercial package is being run from a UNC path or mapped/shared drive, the distribution copy is retained automatically and must be removed manually by authorised IT if required.
