============================================================
1. PACKAGE CONTENTS
============================================================

IMPORTANT DISTRIBUTION NOTE

Do NOT use GitHub's Code > Download ZIP as the installation package. That downloads the developer/source repository.

Use the validated GitHub Actions artifact named:

Pharmagrowth-Stock-Control-Commercial-Package

The artifact only needs to be extracted once. It may be placed in an approved Windows shared folder so the server computer and authorised client computers can access the same commercial package.

After extraction the top level is:

Pharmagrowth Stock Control\
  00 - START HERE - INSTALLATION GUIDE.txt
  01 - INSTALL SERVER.bat
  02 - START SERVER.bat
  03 - STOP SERVER.bat
  04 - SERVER STATUS.bat
  CLIENT DEPLOYMENT\
  Administration & Recovery\
  Documentation\
  System\

The System folder contains controlled server runtime files. IT should not run files directly from System during normal installation.

No self-extracting server or client EXE is required or created.

============================================================
2. SERVER PREREQUISITES
============================================================

- Windows 10/11 Pro or another approved Windows host environment.
- Docker Desktop installed and configured for Linux containers.
- Docker Desktop running before installation.
- Administrator access.
- Stable private LAN IPv4 address or DHCP reservation.
- TCP 8443 permitted between client computers and the server.
- TCP 8088 may be retained for local diagnostics if approved.

The commercial package itself may be stored in a Windows shared folder. The LIVE application and database are not run from the share. "01 - INSTALL SERVER.bat" copies the controlled server runtime to:

C:\ProgramData\Eaststone\StockControl

The PostgreSQL database remains in its controlled local Docker volume.

============================================================
3. INSTALL THE SERVER
============================================================

1. Extract the complete Pharmagrowth Stock Control package. It may be stored in the approved shared folder used for client distribution.
2. On the server computer, start Docker Desktop and wait until Docker is running.
3. Run "01 - INSTALL SERVER.bat" as Administrator.
4. Accept the Windows UAC prompt.
5. The installer copies the controlled server files to C:\ProgramData\Eaststone\StockControl.
6. Confirm the server's private LAN IPv4 address if automatic detection cannot determine it.
   Typical private addresses begin 10.x.x.x, 172.16-31.x.x or 192.168.x.x.
7. Leave the installer window open until both of these are confirmed:

   Server installation completed
   Client deployment verified for server IP: <server IP>

8. Open https://stock-control.test:8443/.
9. Initial login: admin / Admin123!
10. Change the administrator password immediately.
11. Review the generated IQ report:

C:\ProgramData\Eaststone\StockControl\deployment-records\ESC-IQ-Execution-Latest.html

The server setup configures the database, application, HTTPS certificate, trusted private CA, local hostname, firewall rules, scheduled health monitoring, certificate renewal, the always-on configurable daily backup service and application shortcuts.

After installation, open the ESC Backup Settings shortcut on the server to browse to the required backup folder and set the automatic daily time/retention. The settings can be changed again later without reinstalling.

============================================================
4. CLIENT DEPLOYMENT
============================================================

CLIENT DEPLOYMENT is a complete BAT-based client package from the moment the commercial ZIP is extracted.

Before server installation it contains:

01 - INSTALL CLIENT.bat
02 - UNINSTALL CLIENT.bat
Configure-Hosts.ps1
client-config.ini
README.txt

Before server installation, SERVER_IP is intentionally blank and stock-control-ca.crt does not yet exist. Do not install clients until the server installer has finalised the folder.

During server installation, "01 - INSTALL SERVER.bat" does NOT build or create a client installer or EXE. It finalises the SAME CLIENT DEPLOYMENT folder by:

- writing the actual server hostname/IP into client-config.ini
- adding stock-control-ca.crt, the public Stock Control CA certificate
- verifying the published shared client package before reporting success

After successful server installation the SAME shared folder must contain:

01 - INSTALL CLIENT.bat
02 - UNINSTALL CLIENT.bat
Configure-Hosts.ps1
client-config.ini
stock-control-ca.crt
README.txt

To configure another Windows computer:

1. On the client computer, browse to the same approved shared/network CLIENT DEPLOYMENT folder. You may also copy the complete folder locally if preferred.
2. Right-click "01 - INSTALL CLIENT.bat" and select "Run as administrator".
3. Accept UAC.
4. The installer stages the required client files into a local temporary folder before elevation, then imports the public Stock Control CA, maps stock-control.test to the server LAN IP, creates the application shortcut and verifies HTTPS access.
5. Open the Eaststone Stock Control shortcut.
6. Log in using that user's individual Stock Control account.

This reproduces the client deployment behaviour proven in the previous working Windows deployment checkpoint.

Never copy server private keys to a client. Only stock-control-ca.crt is distributed.

CLIENT UNINSTALL

To remove Stock Control client configuration from a client computer, run:

02 - UNINSTALL CLIENT.bat

as Administrator. It removes only that computer's Stock Control shortcut, hosts mapping, trusted client CA and HKLM\SOFTWARE\Eaststone\StockControlClient registration. It does NOT remove the server, database, stock data or shared CLIENT DEPLOYMENT folder.

============================================================
5. NORMAL SERVER CONTROLS
============================================================

Use only the top-level controls during routine operation:

02 - START SERVER.bat
03 - STOP SERVER.bat
04 - SERVER STATUS.bat

The controlled stop preserves the PostgreSQL data volume. Do not use "docker compose down -v" during routine operation because -v destroys the database volume.

============================================================
6. ADMINISTRATION, RECOVERY AND SERVER COMPLETE UNINSTALL
============================================================

Administration & Recovery contains:

01 - BACKUP SETTINGS.bat
02 - BACKUP AND RESTORE.bat
03 - COMPLETE UNINSTALL.bat
README.txt

"01 - BACKUP SETTINGS.bat" browses to the physical server backup folder and changes the daily schedule/retention. "02 - BACKUP AND RESTORE.bat" creates manual backups and browses for a restore file.

"03 - COMPLETE UNINSTALL.bat" is the one supported SERVER uninstall control. There is no duplicate UNINSTALL_WINDOWS.bat under System and there is no uninstall EXE.

This is separate from "CLIENT DEPLOYMENT\02 - UNINSTALL CLIENT.bat", which only removes one client's local configuration.

Server complete uninstall requires explicit confirmations before destroying the PostgreSQL data volume and generated application data. It can also remove:

C:\ProgramData\Eaststone\StockControl

and, when explicitly confirmed and the package is local, the extracted Pharmagrowth Stock Control folder. If the commercial package is on a UNC or mapped/shared location, the distribution copy is retained automatically.
