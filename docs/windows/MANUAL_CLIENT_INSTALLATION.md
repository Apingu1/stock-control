# Manual Client Installation — Fallback Procedure

Use `CLIENT DEPLOYMENT\01 - INSTALL CLIENT.bat` as the recommended client deployment. This manual procedure reproduces the same trust, hostname and shortcut steps when the controlled client launcher cannot be used.

## Information required from the server

Obtain the controlled client deployment package containing:

```text
stock-control-ca.crt
client-config.ini
```

`client-config.ini` records:

```ini
TLS_HOSTNAME=stock-control.test
SERVER_IP=192.168.1.115
APP_HTTPS_PORT=8443
```

Use the actual values generated by the installed server.

Do not accept or copy:

```text
stock-control-ca.key
stock-control.key
```

Those are private server keys and must never leave the host.

## 1. Confirm network access

From the client computer, open Command Prompt:

```bat
ping 192.168.1.115
```

Ping may be blocked by company policy, so also test the application port after server setup:

```powershell
Test-NetConnection 192.168.1.115 -Port 8443
```

`TcpTestSucceeded` should be `True`.

## 2. Import the public CA

1. Double-click `stock-control-ca.crt`.
2. Select **Install Certificate**.
3. Select **Local Machine**.
4. Approve the administrator prompt.
5. Select **Place all certificates in the following store**.
6. Select **Trusted Root Certification Authorities**.
7. Finish the wizard.

Only the public `stock-control-ca.crt` is imported.

Command-line alternative, run Command Prompt as Administrator:

```bat
certutil.exe -addstore -f Root stock-control-ca.crt
```

## 3. Configure hostname resolution

Internal company DNS is preferred. Ask IT to create:

```text
stock-control.test -> 192.168.1.115
```

When DNS is unavailable, edit the local Windows hosts file.

1. Open Notepad as Administrator.
2. Open:

```text
C:\Windows\System32\drivers\etc\hosts
```

3. Change the file selector to **All Files**.
4. Add:

```text
192.168.1.115 stock-control.test
```

5. Save as exactly `hosts`.
6. Run:

```bat
ipconfig /flushdns
ping stock-control.test
```

The ping line should show the recorded server IP.

Helper alternative, run PowerShell as Administrator from the client package:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File Configure-Hosts.ps1 -Hostname stock-control.test -IpAddress 192.168.1.115
```

## 4. Open and verify HTTPS

Close every Chrome/Edge window, reopen the browser and open:

```text
https://stock-control.test:8443
```

Expected outcome:

- the Stock Control login page loads;
- there is no certificate warning;
- the browser shows a secure connection;
- the user can log in with their individual account.

Never use `http://stock-control.test:8443`; port 8443 requires `https://`.

## 5. Create an app shortcut

### Simple desktop URL shortcut

Right-click the desktop, select **New → Shortcut**, and use:

```text
https://stock-control.test:8443
```

Name it:

```text
Eaststone Stock Control
```

### Edge app-window shortcut

Create a shortcut whose target is similar to:

```text
"C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" --app=https://stock-control.test:8443/
```

The exact Edge path can vary.

### Browser PWA installation

In Chrome or Edge, open the HTTPS site and use the browser’s **Install app** command. This requires trusted HTTPS and a valid service worker/manifest. Company IT can force-install the web app through managed Edge policy where available.

## 6. Client acceptance check

Record:

- computer name;
- Windows user;
- installation date;
- certificate thumbprint;
- resolved server IP;
- successful login;
- shortcut/PWA creation;
- tester and reviewer signatures.

## Common problems

### Site cannot be reached

- Confirm the URL uses `https://`.
- Confirm the server is running.
- Confirm `stock-control.test` resolves to the correct server IP.
- Confirm TCP 8443 is open between client and server.

### Certificate warning

- Confirm the public CA was imported into **Local Computer → Trusted Root Certification Authorities**.
- Confirm the certificate copied from the server is the current `stock-control-ca.crt`.
- Close and reopen all browser windows.
- Confirm the hostname is exactly the hostname present in `client-config.ini`.

### A certificate was imported before HTTPS was regenerated

If a new private CA was deliberately generated after the client imported the old CA, import the new public CA. Normal automatic server-certificate renewal does not replace the CA and does not require re-importing it.
