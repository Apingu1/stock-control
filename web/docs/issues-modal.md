# Consumption / Issues Modal (IssueModal)

## Purpose

Creates an atomic multi-material consumption submission or edits an individual
material transaction against a specific lot.

Supports:
- Create multi-material consumption (`POST /issues/batch`)
- Edit issue (PUT) with audit reason
- Lot-first typeahead selection and traceability
- Consumption types affecting required fields
- Shared batch output details and a scrollable material list

## Key files

### `src/components/modals/IssueModal.tsx`
Container/orchestrator:
- Delegates create mode to `BatchIssueCreateModal`
- Retains the audit-trailed individual edit workflow
- Applies superuser rules:
  - in edit mode, can optionally allow changing material/lot if `canSuperEditLockedFields` is true

Endpoints:
- `POST /issues/batch`
- `PUT /issues/{id}`

### `src/components/modals/BatchIssueCreateModal.tsx`
Create-mode workflow:
- shared consumption/batch header entered once
- repeatable material cards
- lot-number typeahead across positive-balance lot segments
- automatic material, expiry, status, manufacturer, UOM and balance display
- duplicate exact lot-segment prevention
- rejected lots blocked
- quarantined lots disabled when policy is blocked and warned when policy is warn-only
- one atomic API submission so partial batches cannot be posted

Payload fields commonly included:
- `material_code`, `lot_number`, `material_lot_id`
- `qty`, `uom_code`
- `consumption_type`
- `es_product_code` (may be null)
- `product_batch_no`, `product_manufacture_date` (conditional)
- `total_batch_size`, `batch_size_uom`, `number_of_units`
- `consumption_group_id` (generated by backend)
- `comment`
- `edit_reason` (edit only)

## Behaviour rules (important)

- **Consumption type rules**
  - USAGE: product code, batch number, manufacture date, total batch size/unit and number of units required
  - R_AND_D: batch fields optional
  - WASTAGE/DESTRUCTION: batch fields hidden/irrelevant
  - DESTRUCTION: comment required

- **Atomic posting**
  - all material lines are validated before commit
  - any invalid line rolls back the complete submission
  - every stored material remains an individual ISSUE row
  - rows from one submission share a `consumption_group_id`

- **Grouped editing**
  - quantity changes affect the selected material row
  - shared batch/output corrections are applied to all rows in the group
  - each affected row receives an immutable edit-audit entry using the supplied reason

- **Edit reason**
  - Required on edit (audit trail)

- **Traceability locking**
  - Normal edit: material/lot are fixed
  - Superuser edit: material/lot may be changed (still audit-trailed)

- **Lot sorting**
  - AVAILABLE segments displayed first
  - Then QUARANTINE
  - Then REJECTED
